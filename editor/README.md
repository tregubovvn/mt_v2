## 📖 Описание

**Moodle XML Редактор** — одностраничное клиентское приложение (frontend-only) для создания, редактирования и публикации тестов в формате экспорта LMS **Moodle XML**.

Приложение задумано как «мост» между преподавателем и студентом:

```
┌──────────────┐   «Загрузить файл»   ┌──────────────────┐    «Новый GIST»    ┌─────────────┐
│  10_2.xml    │ ───────────────────▶ │  РЕДАКТОР        │ ─────────────────▶ │ GitHub Gist │
│  (из Moodle) │                      │  (этот проект)   │    автосохранение  │  (облако)   │
└──────────────┘                      └──────────────────┘                    └──────┬──────┘
                                            ▲                                        │ raw_url
                            «Применить      │                          «Открыть тест»│
                            изменения»      │                                        ▼
                                      XML ↔ Форма                    ┌─────────────────────────┐
                                                                      │ Приложение тестирования │
                                                                      │  index.html?name=<url>  │
                                                                      └─────────────────────────┘
```

Приложение полностью работает **в браузере**: не требует серверной части, базы данных, Node.js или сборщиков. Всё приложение — один HTML-файл, который можно открыть локально или разместить на GitHub Pages.

> [!NOTE]
> Редактор работает **только с вопросами типа `multichoice`** (множественный выбор с одним правильным ответом) — это единственный тип, который корректно проходит полный цикл «редактирование → экспорт → прохождение теста». Вопросы других типов при импорте пропускаются.

## 🔧 Подробное описание функциональности

### 1. Редактор вопросов

Основная рабочая область. Отображает **по одному вопросу за раз** — актуально для тестов с формулами, где вопросы объёмные.

**Навигация:**

| Элемент | Действие |
|---|---|
| Вкладки `1 2 3 …` | Прямой переход к вопросу по номеру; подсказка при наведении показывает название вопроса |
| `◀ Назад` / `Вперёд ▶` | Последовательное переключение; кнопки автоматически блокируются на краях диапазона |
| `+ Добавить вопрос` | Создаёт новый вопрос в конце списка и сразу открывает его |
| `⧉ Дублировать` | Создаёт полную копию текущего вопроса (включая формулы и ответы) и вставляет **сразу после** него — удобно для однотипных вопросов |
| 🗑 (иконка в карточке) | Удаление текущего вопроса **с подтверждением**; последний вопрос удалить нельзя |

**Поля вопроса:**

| Поле | Соответствие в XML | Описание |
|---|---|---|
| Название вопроса | `<name><text>` | Служебное имя в банке вопросов Moodle (студенту не показывается) |
| Текст вопроса | `<questiontext><text>` | HTML-текст с формулами; многострочное поле |
| Перемешивать ответы | `<shuffleanswers>` | `true` / `false` — перемешивать ли варианты при показе |
| Нумерация ответов | `<answernumbering>` | `abc` · `ABC` · `123` · `none` — влияет на предпросмотр |

---

### 2. Панель вставки формул

Расположена под полем текста вопроса. Сниппет вставляется в **позицию курсора** последнего активного поля (текст вопроса **или** любой из ответов). Если в поле выделен текст — он **оборачивается** в конструкцию (например, выделенное `a+b` при нажатии «x/y» станет `\frac{a+b}{}`).

| Кнопка | Вставляемый код | Назначение |
|:---:|---|---|
| `\(…\)` | `\( ... \)` | Обёртка строчной формулы |
| `\[…\]` | `\[ ... \]` | Обёртка выносной формулы |
| `x/y` | `\frac{...}{...}` | Дробь |
| `√x` | `\sqrt{...}` | Квадратный корень |
| `xⁿ` | `^{...}` | Верхний индекс (степень) |
| `xₙ` | `_{...}` | Нижний индекс |
| `text` | `\text{...}` | Текст внутри формулы — **обязательно для кириллицы** |
| `α` | `\alpha` | Греческие буквы и символы: |
| `β` | `\beta` | |
| `π` | `\pi` | |
| `×` | `\times` | Умножение |
| `±` | `\pm` | Плюс-минус |
| `≤` | `\leq` | Меньше или равно |
| `≥` | `\geq` | Больше или равно |
| `≠` | `\neq` | Не равно |
| `∞` | `\infty` | Бесконечность |

После вставки курсор автоматически позиционируется внутри сниппета, а изменение немедленно синхронизируется с XML и предпросмотром.

> [!TIP]
> Формулы хранятся внутри `CDATA`-секций XML, поэтому обратные слэши **не требуют двойного экранирования** — пишите `\frac{АД_{сэ}}{АД_{с}}` как есть.

---

### 3. Редактор вариантов ответов

Для каждого вопроса доступно **неограниченное** количество вариантов (минимум — 2, при попытке удалить лишний показывается предупреждение).

| Элемент строки ответа | Описание |
|---|---|
| ⚪ Радио-кнопка | Клик помечает вариант **правильным**: он получает `fraction="100"`, все остальные — `fraction="0"`. Механика «один правильный ответ» |
| Бейдж `100%` / `0%` | Наглядная индикация веса ответа (зелёный/серый) |
| Подсветка рамкой | Правильный ответ выделяется голубой рамкой и фоном |
| Поле ввода | Текст ответа — HTML, поддерживает формулы `\( ... \)` |
| ✕ | Удаление варианта |

Кнопка `+ Добавить ответ` добавляет пустой неправильный вариант в конец списка.

### 4. Предпросмотр с MathJax

Карточка **«Предпросмотр (MathJax)»** показывает вопрос ровно так, как его увидит студент в приложении тестирования:

- HTML текста вопроса рендерится как разметка;
- формулы `\( ... \)` и `\[ ... \]` преобразуются MathJax в типографскую вёрстку;
- варианты подписываются согласно выбранной нумерации (`a.`, `A.`, `1.` или маркер);
- правильный ответ помечается зелёной рамкой и меткой **«✓ верно»**.

> [!NOTE]
> Обновление предпросмотра выполняется с дебаунсом **350 мс** после остановки ввода — это исключает «дребезг» MathJax при быстрой печати и не тормозит интерфейс.

### 5. Двусторонняя синхронизация с XML

Сердце редактора — внутренняя модель данных (`quizData`), из которой генерируется XML и в которую парсится введённый XML.

```
        ФОРМА (ввод)                       XML-ПАНЕЛЬ
             │                                   │
             │  любое изменение                  │  кнопка «Применить
             │  (input/change)                   │  изменения»
             ▼                                   ▼
        ┌─────────────────────────────────────────────┐
        │        МОДЕЛЬ ДАННЫХ (quizData)             │
        │  { questions: [ { name, text,               │
        │      shuffleanswers, answernumbering,       │
        │      answers: [ {text, correct} ] } ] }     │
        └─────────────────────────────────────────────┘
             ▲                                   ▲
             │  renderQuestion()                 │  generateXml()
             │  + renderPreview()                │  (авто, ~100 мс)
             │                                   │
        ВИЗУАЛЬНЫЙ РЕДАКТОР +              ТЕКСТ XML В ПАНЕЛИ
        ПРЕДПРОСМОМ MATHJAX                (+ автосохранение в Gist)
```

| Направление | Триггер | Задержка |
|---|---|---|
| Форма → XML | Любое изменение в полях | ~100 мс (дебаунс) |
| XML → Форма | Кнопка **«Применить изменения»** | мгновенно |
| Любое изменение → Gist | Автосохранение | 1500 мс (дебаунс) |

> [!WARNING]
> Ручные правки XML **не применяются** к форме автоматически — после правки кода вручную обязательно нажмите «Применить изменения», иначе при следующем изменении в форме ваши правки будут перезаписаны.

### 6. XML-панель

Нижняя закреплённая панель с моноширинным редактором XML.

| Кнопка | Действие |

### 7. Хранение в GitHub Gist

Тесты хранятся как файлы `quiz.xml` внутри приватных GitHub Gist — это бесплатное «облако» с прямыми raw-ссылками, которые умеет читать приложение тестирования.

| Действие | Механика |
|---|---|
| **Новый GIST** | `POST /gists` — создаётся приватный Gist с файлом `quiz.xml`; описание = название теста. В шапке появляется ссылка на Gist |
| **Автосохранение** | Через 1,5 с после последнего изменения — `PATCH /gists/{id}`. Если сохранение уже идёт, новая операция ставится в очередь (`needsAnotherSave`). При конфликте «blocked» — автоматический повтор |
| **Загрузить GIST** | Модальное окно принимает: полную ссылку `gist.github.com/...`, raw-ссылку `gist.githubusercontent.com/...`, ссылку приложения тестирования (`?file=...`) или голый ID |
| **Raw URL** | После каждого сохранения обновляется; используется кнопкой «Открыть тест» |

Индикация в строке состояния:

```
Готово → Есть несохранённые изменения... → Сохранение в GIST... → Сохранено в GIST в 14:32:05
```

### 8. Интеграция с DeepSeek AI

Кнопка **«Спросить DeepSeek»** отправляет **всё содержимое XML-панели** в модель `deepseek-chat` как единый user-промпт.

**Рекомендуемый workflow:**

1. Загрузите текст (например, параграф лекции) в XML-панель;
2. Допишите инструкцию прямо в тексте:
   ```text
   Сгенерируй 5 вопросов типа multichoice по этому материалу.
   Ответы с формулами оформи как \( ... \), кириллицу в формулах —
   в \text{}. Верни ТОЛЬКО валидный Moodle XML без пояснений.
   ```
3. Нажмите «Спросить DeepSeek» — ответ заменит содержимое панели;
4. Проверьте и нажмите **«Применить изменения»**;
5. Результат автоматически уйдёт в Gist.

> [!WARNING]
> Ответ AI не валидируется автоматически — модель может вернуть пояснительный текст вокруг XML. Перед «Применить изменения» убедитесь, что в панели остался только XML (валидность проверит парсер).

---

### 9. Кнопка «Открыть тест»

Завершающий шаг публикации. По нажатию:

1. Открывается новая вкладка **синхронно** (обход блокировщиков всплывающих окон);
2. Pending-изменения **принудительно досохраняются** в Gist;
3. Вкладка перенаправляется на приложение тестирования:
   ```
   https://tregubovvn.github.io/mt_v2/index.html?name=<raw_url>
   ```
4. Ссылка копируется в буфер — её можно разослать студентам (или завернуть в QR-код).

Студент, открывший ссылку, увидит только окно ввода ФИО и сразу перейдёт к тесту — секция загрузки по ссылке будет скрыта.

## 🚀 Установка и запуск

### Шаг 1 — получите токены

<details>
<summary><b>GitHub Token</b> — нужен для сохранения/загрузки Gist (нажмите, чтобы раскрыть)</summary>

1. Откройте [github.com/settings/tokens/new](https://github.com/settings/tokens/new);
2. Задайте имя и срок действия токена;
3. Отметьте право **`gists`** → *Read and write*;
4. Нажмите *Generate token* и скопируйте значение.
</details>

<details>
<summary><b>DeepSeek Token</b> — нужен только для AI-генерации (необязательно)</summary>

1. Зарегистрируйтесь на [platform.deepseek.com](https://platform.deepseek.com/);
2. Раздел [API Keys](https://platform.deepseek.com/api_keys) → *Create new API key*;
3. Скопируйте ключ (начинается с `sk-`).
</details>

## 📐 Работа с формулами LaTeX

### Синтаксис

| Нотация | Тип | Пример | Результат |
|---|---|---|---|
| `\( ... \)` | строчная формула | `Значение \(E = mc^2\)` | формула в строке текста |
| `\[ ... \]` | выносная формула | `\[\int_0^1 x\,dx\]` | формула отдельным блоком |

### Примеры типичных конструкций

```latex
\( \alpha_{\text{н}} = \frac{\text{АД}_{\text{сэ}}}{\text{АД}_{\text{с}}} \)   % дробь + русские индексы
\( a^2 + b^2 = c^2 \)                                                        % теорема Пифагора
\( \sqrt{b^2 - 4ac} \)                                                       % дискриминанта
\( \text{КПД} = \frac{A_{\text{полезн}}}{A_{\text{затр}}} \times 100\% \)      % проценты
```

### Где работают формулы

- ✅ в тексте вопроса;
- ✅ в тексте любого варианта ответа;
- ✅ в предпросмотре редактора;
- ✅ в приложении тестирования (вопрос, ответы, детальный разбор результатов).

> [!IMPORTANT]
> Кириллицу внутри формул оборачивайте в `\text{...}`: не `\(АД_с\)`, а `\( \text{АД}_{\text{с}} \)` — иначе MathJax отрисует буквы некорректно.

## 📄 Формат файла теста

Редактор работает с форматом **Moodle XML**, тип вопроса `multichoice`.

### Что редактор читает и пишет

```xml
<?xml version="1.0" encoding="UTF-8"?>
<quiz>
    <question type="multichoice">
        <name>
            <text>Коэффициент нервной регуляции</text>          <!-- ✏️ поле "Название" -->
        </name>
        <questiontext format="html">
            <text><![CDATA[<p>Выберите формулу: \( \alpha \)</p>]]></text>  <!-- ✏️ текст вопроса -->
        </questiontext>
        <generalfeedback format="html"><text></text></generalfeedback>      <!-- ⚙️ генерируется -->
        <defaultgrade>1.0</defaultgrade>                                    <!-- ⚙️ генерируется -->
        <penalty>0.3333333</penalty>                                        <!-- ⚙️ генерируется -->
        <hidden>0</hidden>                                                  <!-- ⚙️ генерируется -->
        <single>true</single>                                               <!-- ⚙️ генерируется -->
        <shuffleanswers>true</shuffleanswers>                               <!-- ✏️ выпадающий список -->
        <answernumbering>abc</answernumbering>                              <!-- ✏️ выпадающий список -->
        <answer fraction="100" format="html">
            <text><![CDATA[\( \alpha = \frac{АД_{сэ}}{АД_{с}} \)]]></text>  <!-- ✏️ вариант, ✓ правильный -->
        </answer>
        <answer fraction="0" format="html">
            <text><![CDATA[\( \alpha = \frac{АД_{с}}{АД_{сэ}} \)]]></text>  <!-- ✏️ вариант -->
        </answer>
    </question>
</quiz>
```

### Матрица поддержки элементов

| Элемент | Импорт | Экспорт | Примечание |
|---|:---:|:---:|---|
| `<question type="multichoice">` | ✅ | ✅ | единственный поддерживаемый тип |
| `<question type="...">` прочие | ⏭ | — | пропускаются при парсинге |
| `<name>`, `<questiontext>` | ✅ | ✅ | |
| `<answer fraction="N">` | ✅ | ✅ | `fraction > 0` → правильный; при экспорте нормализуется в `100`/`0` |
| `<shuffleanswers>`, `<answernumbering>` | ✅ | ✅ | |
| `<single>`, `<defaultgrade>`, `<penalty>`, `<hidden>` | ℹ️ | ⚙️ | при экспорте подставляются стандартные значения |
| `<generalfeedback>`, `<feedback>`, `<tags>`, категории `$course$` | ⏭ | ⚙️ | при сохранении отбрасываются |
| Формулы `\( \)`, `\[ \]` в CDATA | ✅ | ✅ | без экранирования слэшей |

> [!NOTE]
> Файлы, созданные редактором, **полностью совместимы с Moodle**: их можно импортировать обратно в банк вопросов курса (*Банк вопросов → Импорт → Формат Moodle XML*).

## 🗺 Карта функций кода

| Функция | Назначение |
|---|---|
| `parseXmlToData(xml)` | Moodle XML → модель редактора; защита от parsererror; фильтрация по `type="multichoice"` |
| `generateXml()` | Модель → Moodle XML: CDATA, стандартные поля, отступы |
| `cdata(str)` | Оборачивание в `<![CDATA[...]]>` с защитой от разрыва `]]>` |

| `renderQuestion()` / `renderAnswers()` | Перерисовка формы под текущий вопрос |
| `renderPreview()` / `schedulePreview()` | Предпросмотр + MathJax `typesetPromise([box])` с дебаунсом 350 мс |
| `ins(before, after)` | Вставка LaTeX-сниппета в позицию курсора последнего поля, с оборачиванием выделения |
| `updateXmlOutput()` | Дебаунс-генерация XML (~100 мс) + запуск автосохранения |
| `applyXmlChanges()` | Ручное применение правок XML → форма |
| `loadXmlFromFile(input)` | FileReader: файл с диска → XML-панель → модель → (опц.) новый Gist |
| `createNewGist()` | `POST /gists`, сохранение `id`, `html_url`, `raw_url` |
| `autoSaveToGist()` | `PATCH /gists/{id}`; очередь сохранений; retry при «blocked» |
| `loadFromGist()` | Загрузка по ссылке/ID; автоопределение XML-файла в Gist |
| `extractGistId(input)` | Извлечение ID из любых форм ссылок (gist, raw, `?file=`) |
| `openTest()` | Синхронное открытие вкладки + flush автосохранения + редирект на `index.html?name=<raw>` |
| `askDeepSeek()` | `POST api.deepseek.com/chat/completions`, вставка ответа в XML-панель |
| `initResizer()` | Drag-изменение высоты XML-панели (100–600 px) |
| `showToast()` / `setStatus()` | Уведомления и строка состояния |

## 💾 Хранение данных

| Данные | Где хранятся | Жизненный цикл |
|---|---|---|
| Токены GitHub / DeepSeek | `localStorage` браузера | до очистки хранилища |
| Текст теста (XML) | GitHub Gist (`quiz.xml`) | бессрочно, редактируется из любого браузера |
| Ссылка на Gist | только в текущей сессии (память) | до перезагрузки страницы — сохраните ссылку |

> [!TIP]
> Скопируйте ссылку Gist из шапки после создания — она позволит продолжить работу с тестом с другого устройства через «Загрузить GIST».

## 🔐 Безопасность

- Токены хранятся **только локально** (`localStorage`) и передаются **напрямую** в API GitHub/DeepSeek по HTTPS;
- Редактор не имеет собственного бэкенда и не отправляет токены куда-либо ещё;
- GitHub-токену рекомендуется выдавать **минимальные права** (только `gists`) и ограниченный срок действия;
- Gist'ы создаются **приватными** (`"public": false`), однако любой, кто знает ссылку/raw-URL, сможет прочитать тест — не размещайте в тесте закрытую информацию;
- Не публикуйте свои токены в репозитории и скриншотах.

---

## ⚠️ Ограничения и известные проблемы

- **Только `multichoice`** — вопросы `truefalse`, `shortanswer`, `essay`, `cloze` при импорте пропускаются;
- **Один правильный ответ** — если в загруженном файле несколько `fraction > 0`, правильным останется только первый; частичные баллы (`50`, `33.3`) не поддерживаются;
- **Отбрасываемые поля** — `generalfeedback`, `feedback` вариантов, теги, категории не сохраняются при экспорте;
- **Ручные правки XML** не применяются к форме без нажатия «Применить изменения»;
- **DeepSeek** может вернуть текст вокруг XML — ответ нужно проверить перед применением;
- **CDN-зависимости** (MathJax) — при первом запуске нужен интернет;
- **Токены в localStorage** — при работе на общем компьютере используйте режим инкогнито или очищайте поля перед выходом.

## 🩺 Решение проблем

| Симптом | Причина и решение |
|---|---|
| Формулы в предпросмотре показываются как `\frac{...}` | Формула не обёрнута в `\( ... \)`; либо MathJax не загрузился — проверьте консоль (F12) и доступ к CDN |
| Кириллица в формуле отображается неверно | Оберните её в `\text{...}` |
| «Требуется GitHub Token» | Введите токен в шапке — см. [Установка](#шаг-1--получите-токены) |
| «Ошибка XML: некорректный XML» | Проверьте теги; вставьте XML в любой валидатор; убедитесь, что AI вернул XML без сопроводительного текста |
| Статус «blocked» при сохранении | Gist занят предыдущим запросом — редактор повторит попытку автоматически |
| Студент не видит последний вопрос | Дождитесь «Сохранено в GIST» или нажмите «Открыть тест» — она досохраняет изменения перед публикацией |
| 401/403 от GitHub | Токен просрочен или без права `gists` — сгенерируйте новый |
| Пропали вопросы при загрузке файла | В файле нет вопросов `multichoice` — проверьте типы в исходном XML |

## ❓ Часто задаваемые вопросы

<details>
<summary><b>Можно ли редактировать тест, экспортированный из Moodle?</b></summary>

Да. Экспортируйте банк вопросов в *«Формат Moodle XML»* и загрузите файл через XML-панель. Вопросы `multichoice` отредактируются; результат можно импортировать обратно в Moodle.
</details>

<details>
<summary><b>Работает ли редактор без GitHub?</b></summary>

Да. Токен нужен только для облачного хранения. Можно редактировать вопросы и копировать XML кнопкой «Копировать» (или сохранить файл вручную из XML-панели средствами браузера).
</details>

<details>
<summary><b>Где взять ссылку, которую можно дать студентам?</b></summary>

Кнопка «Открыть тест» кладёт её в буфер обмена автоматически. Вручную: ссылка Gist в шапке → raw_url → `https://tregubovvn.github.io/mt_v2/index.html?name=<raw_url>`.
</details>

<details>
<summary><b>Можно ли работать с одного теста с двух устройств?</b></summary>

Да: на втором устройстве откройте редактор, введите тот же токен и загрузите Gist по ссылке через «Загрузить GIST». Изменения продолжат автосохраняться в тот же Gist.
</details>

<details>
<summary><b>Почему в предпросмотре варианты подписаны «a., b., c.», а в тесте их порядок другой?</b></summary>

В вопросе включено `shuffleanswers = true`: Moodle и приложение тестирования перемешивают варианты при показе. Отключите перемешивание в выпадающем списке, если порядок важен.
</details>
